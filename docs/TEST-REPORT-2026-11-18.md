## 三、这次发现并修掉的问题（3 个）

### 1. 空输入"点了发送没反应" 【已修】

**实测**：

```
输入 "   " → 0.1 s 返回
回复内容 = 上一轮回复原样（"已更新参数：直径调整为 45mm…"）
```

用户会以为卡住了。而且它连输入框都没清。

**修法**：空输入明确回一句引导，并清空输入框。

```
空输入 → "想做一个什么？一句话就行 —— 比如「一个直径 90mm 的六边形笔筒，壁厚 3mm」。
         也可以先上传一张图片，我按图改。"
```

**复测**：✓（0.1 s）

---

### 2. 手工启动的 app 没有日志 【已修】

**实测**：`logs/studio-app.log` 最后写入是 **634 分钟前**，而 app 正在跑。
原因：那个文件只有 **Studio 启动的子进程**才写；手工双击 `启动.bat` 或命令行跑 `python app.py`，日志只进控制台，**关窗口就没了**。

排查问题时会直接卡住（这次找"点了没反应"就卡在这）。

**修法**：app 启动时把 stdout/stderr 做 Tee，同时写 `logs/app-YYYY-MM-DD.log`。

**验证**：

```
logs/app-2026-11-18.log   已生成并在写
```

---

### 3. 身份接口不统一 【已记录，低优先】

`app` 有 `/__forgeform_id`（返回 JSON 身份），而 Studio / API 只回响应头 `X-ForgeForm-Root`。
功能没问题（我自己测的时候踩了一下），但对第三方排查脚本不友好。

**建议**：三处都提供 `/__forgeform_id`。约 20 行改动。

## 四、仍然存在的问题（3 个，未修）

### P1 作品列表里大部分是空壳 【待办】

**实测**：

```
projects/ 25 个目录，其中 20 个没有 candidates 图（80%）
```

这些是"新建对话组但没出图"留下的。界面上点开是空的，用户会觉得"我的作品丢了/坏了"。

**建议**：侧栏列表把它们标成「未生成」并置灰，或默认只列有产物的；打开空作品时给一句"这组还没出图，点🎨试试"。

---

### P2 冷启动第一轮对话很慢（92–105 s）【已知，缓了一部分】

`agent.warm_up()` 在启动 15 s 后后台跑（实测 88 s），但如果用户在这之前就发消息，就要等。

**现状**：可用，但慢。**建议**：首屏加一句"正在准备对话模型（约 90 秒）"，比干等好。

---

上次实测：48 分钟不出结果 / 24.4 分钟把 ComfyUI 弄崩。
