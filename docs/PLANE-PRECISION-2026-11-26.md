# 接续 Codex：飞机建模精度（2026-11-26 上午）

接 Codex 停在「精度太低」之后的活。这一轮做了三件事：**把评估口径修对**、**把 Codex 的三个未完成实验跑掉**、**把他卡住的编译依赖打通**。

## 一、先修评估口径（前面几轮的 IoU 数字不可信）

### 问题 1：v1 把两个剪影都硬拉成 512×512

等于把**宽高比**这个最重要的误差维度消掉了 —— 翼展差 3 倍也测不出来。
v1 里那个「翼展 ×1.0~4.0 扫参全部 0.4988 一模一样」的怪现象，就是这个 bug。

### 问题 2：v2 用「24 种轴排列取最大 IoU」找朝向

这是**让指标自己优化自己**。Codex 的模型是 Y-up、铸想导出的是 z-up，混着比会乱。

### 现在的口径（v4）

- 剪影裁到 bbox → 长边等比缩放到 512 → 居中放进 512² 画布（**保留宽高比**）
- 高度轴 = 最小尺寸轴（飞机无争议）
- 长度轴在 X/Y 里**只做一次二选一**，用侧视 IoU 判
- 允许水平翻转

### 修正后的排名（同一口径）

| 配置 | 侧视 | 正视 | 俯视 | 平均 |
|---|---|---|---|---|
| **2.1 @512 · 侧视输入** | **0.699** | 0.431 | 0.283 | **0.4709** |
| 2.1 @512 · 正视输入 | 0.663 | 0.462 | 0.296 | 0.4740 |
| 2.1 @768 · 侧视 | 0.668 | 0.447 | 0.276 | 0.4635 |
| 2mini @512 · 侧视 | 0.685 | 0.378 | 0.293 | 0.4519 |
| 合成多视图（Zero123Plus 6 视图 → 2mv） | 0.560 | 0.242 | 0.168 | 0.3233 |
| Codex 512 基线（真实照片 + U2Net 抠图） | 0.275* | 0.443 | 0.260 | 0.3257* |

\* Codex 基线那行的侧视偏低是朝向判定差异，不能直接横比；**同一口径下它不如我的单图**。

**结论没变：单图 2.1@512 最好；合成多视图最差。** 正视输入其实和侧视打平（0.4740 vs 0.4709），差异在噪声范围内。

## 二、Codex 三个未完成实验的结果

### ① 真实照片 + 自产遮罩 → 2mv：**比合成多视图还差（0.267）**

做法（针对 Codex 的发现对症下药）：
- 自产 alpha 遮罩（阈值 + 开运算 + 外扩 3px），节点看到非全不透明 alpha 就跳过 U2Net —— 不会再丢机翼
- 四视图统一把包围盒高度缩到 800 px，消掉尺度差

结果：front 0.176 / side 0.474 / top 0.152，平均 0.267，**比 Codex 的 U2Net 版本（0.3257）还低**。

**根因**：这 5 张照片的**仰角不一致**——正视略仰、背视是俯视机尾、侧视是平视。2mv 拿到的是四组互相矛盾的方位约束，遮罩修得再好也救不回来。

这印证了 Codex 的判断：**瓶颈在输入几何，不在模型参数**。

### ② 对称化后处理：**收益为零，方法还不适用**

飞机左右对称（镜像误差 0.148 mm / 200 mm = 0.07%）。
但单图重建出来的是**薄壳实体**（翼展方向只有 52 mm），镜像后最近点会配到"另一面"上 —— 顶点一平均，厚度直接塌成 0（体积 0.01 cm³、水密 False）。
要做得用布尔并集或 SDF 重采样，成本高于收益。**已放弃。**

### ③ 俯视轮廓修正（按俯视宽度曲线逐站位缩放翼展）

- v1 有个轴搞反的 bug（按长度轴缩放），越修越差
- v2 修正轴向：top 0.283 → **0.320**，但 front 0.431 → 0.317，平均 0.4709 → 0.4451，**净损失**

**根因**：模型的翼展其实是对的（200 mm 翼展 / 172 mm 机身长 = 1.16，真机 AG600 是 38.8/36.9 = 1.05，同量级）。俯视 0.28 的差距不是尺度，是**结构**——机翼后掠、浮筒、发动机短舱的位置和形状。

## 三、Codex 卡住的编译依赖：**打通了两个**

Codex 说 Direct3D-V3 缺 `flash_attn` / `cudavoxelize` / `fillhole_cpp`，"暂不能直接宣称可运行"。

实测这台机器有：
```
nvcc 12.8（C:\Program Files\NVIDIA GPU Computing Toolkit\CUDA\v12.8）
VS2022 BuildTools 14.44
torch 2.14.1+cu126 / cc (7,0) / bf16_supported=True
```

于是直接编：

```bat
call vcvars64.bat
set TORCH_CUDA_ARCH_LIST=7.0
set DISTUTILS_USE_SDK=1
python setup.py build_ext --inplace   # third_party/voxelization、third_party/fill_holes
```

**两个都编过了**（EXIT_VOX=0、EXIT_FILL=0）。导入报 `DLL load failed` 是因为缺 PATH，补上就好：

```
CUDA\v12.8\bin ; site-packages\torch\lib ; miniconda3\Library\bin
→ cudavoxelize OK / fillhole_cpp OK
```

**只剩 flash_attn**：FA2 官方只支持 sm80+，V100 是 sm70，编不出来。
Direct3D-V3 的 `sparse_atten.py` 里三处调用（`flash_attn_varlen_kvpacked_func` / `flash_attn_qkvpacked_func` / `flash_attn_varlen_qkvpacked_func`）要改写成 torch SDPA + varlen 打包模拟。
