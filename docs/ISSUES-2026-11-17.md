## 一、先说结论

跑完 17 项功能探测：**生成链路是通的**（出图 77.7 s / 建模 532.1 s / STL 13.2 s / 全部水密），

## 二、阻断级问题

### P0-1 同一台机器两份铸想 → 新装的"点了没反应" 【已修】

**现象**：双击新装的铸想，浏览器打开的是**旧版页面**；Studio 控制台根本打不开。

**实测证据**：

```
pid 18916  pythonw  D:\AI-Workshop\tools\foundry_ondemand.py   ← 旧版，占着 7860
pid 20588  python   app.py                                      ← 旧版派生的子进程，占了 7861
7861 的实际响应：Gradio 页面（不是 Studio），/api/ping → 404
```

于是：

- 新版 `app.py` 探到 7860 有"铸想签名" → 判定"自己人已在跑" → **自己退出**
- Studio 探到 7861 有"铸想签名" → 判定"Studio 已在跑" → **自己退出**

两份都退出，用户什么都没看到。

**修法**（`backend/ports.py`）：

1. 每个服务暴露**身份**：app 用 `/__forgeform_id` 路由，Studio/API 用响应头 `X-ForgeForm-Root`，
   内容都是**自己的根目录**。
2. `who_is()` 比对根目录：**只有同一份安装才算自己人**；另一份安装（如 `D:\AI-Workshop`）当冲突处理。
3. 端口保留：app 换端口时跳过 **7861/7862/7863**；Studio 只认 7861，且端口上蹲着的若不是 Studio 就换端口。

**验证**：

```
7860 /__forgeform_id → {"root":"D:\\ForgeForm-oss","kind":"app","version":"3.7.3"}
模拟另一份安装占 7895 → who_is: ours=True same=False install=D:\AI-Workshop
                        resolve → 改用 7896（不再"复用"）
```

### P0-2 app.py 会抢占 Studio 的 7861 【已修】

换端口逻辑只在 7860 往后找，**不知道 7861/7863 是预留的**。
实测旧版 app 就这样占了 7861，直接把 Studio 挤死（见 P0-1）。

**修法**：`resolve(..., avoid=(7861, 7862, 7863))`。

---

### P0-3 「最高精度」(octree 1024) 在这台机器上跑不完 【需决策】

**实测**：

| 次 | 结果 |
|---|---|
| 第 1 次 | 1200 s 判超时，任务仍在卡上跑，又跑了 45 分钟（占 100% GPU） |
| 第 2 次（给 3600 s） | **48 分钟仍无结果**，手动中止 |
| 第 3 次（给 3600 s） | 24.4 分钟时 **ComfyUI 进程直接崩了**（任务丢失） |

对比 512 octree：**532 s**（8.9 分钟）。768 octree 没跑完过一次（同一批被中断）。

**结论**：1024 在 32 GB V100 上不是"慢"，是**不稳定**。声称"最高精度"却拿不出结果，
比没有这一档更坏。

**建议**（三选一，需要你定）：

- A. UI 上把「最高精度」改成**实验档**，标注"20 分钟以上，可能失败"，默认不选；
- B. 直接下架 1024，最高到「极致 768」；
- C. 保留但改成**后台任务 + 可中断**（用户能去干别的，回来取件）。

我倾向 **A + C**：默认不给、要就给足预期。

---

### P0-4 超时后不撤任务 → 显卡被占死，后面全崩 【已修】

**现象**：一次 3D 超时之后，出图连续两次失败，报 `ComfyUI task timeout after 600s`。

**根因**：`wait_for_completion` 超时只抛异常，**没有把任务从 ComfyUI 撤掉**。
hy3dgen 节点还会忽略 `/interrupt`，任务继续算 —— 实测又占卡 45 分钟，后面所有任务排队。

**修法**（`backend/comfy_client.py`）：

```python
try: self.interrupt()          # 停当前执行
try: self.cancel_prompt(pid)   # 按 id 从 queue_running/queue_pending 删（新增）
raise TimeoutError(...（已尝试撤回该任务）)
```

## 三、体验与数据可信度

### P1-1 出图超时 600 s 太紧 【已修（改 900 s 且可配）】

冷启动（Flux2 + 文本编码器 + VAE 首载）第一张 1024² 会超过 600 s：

```
[18:26] 出图…  →  [18:37] ✗ 出图失败  ComfyUI task timeout after 600s
```

而同一天热起来之后：**55 s / 77.7 s**。
→ `stages.image.timeout_s` 默认 600，可配；本机设 900。

### P1-2 耗时统计被"缓存命中"污染 【已修】

界面上写"实测通常 0.1 秒"，其实是假的：

```
outputs/timings_local.jsonl
  image_512  n=40  最近 [0.08, 0.07, 0.08, 0.06]
  3d_std     n=40  最近 [0.07, 0.06, 0.07, 0.06]
```

**根因**：`record()` 只挡 `<= 0.05 s`，缓存命中/提前返回的 0.07 s 全被当成真实生成记进去。

**修法**：给每个阶段加**物理下限**（出图 ≥8 s、建模 ≥60 s、1024 档 ≥120 s），低于即丢弃；
历史脏样本已归档（`timings_local.bak-1117-2228`），清掉 79 条，剩 6 条真实样本。

清理后：

```
3d_fast: 中位 709 s / p90 922 s（n=5）
```

### P1-3 提示词形状词重复 【已修】

实测日志：

```
a cylindrical simple cylindrical pen holder, … , cylindrical form, sharp geometric edges
```

一句话里 `cylindrical` 出现 3 次。**根因**：`_reinforce_shape()` 只在"句首恰好是形状词"时跳过，
`a simple cylindrical …` 这种"形容词在中间"的句式没被识别。

**修法**：整句里出现该词根就不再注入（首尾两处都改）。

### P1-4 站点版本落后 【待办】

```
本地 VERSION 3.7.3     站点 /foundry 仍写 v3.7.2
```

冒烟测试因此报红。发版后要同步站点直链与文案版本号。

### P1-5 生成后首条对话要等 70–90 s 【部分缓解】

建模前必须让 Strata 让出显存，生成完再拉回：

```
[prewarm] 预热完成 88s          启动预热（已有）
冷启动首条 105.9 s / 热 6–12 s   生成后仍会冷一次
```

可用，但用户会觉得"刚生成完怎么越用越卡"。
