## 一、贴图：Paint-PBR 2.1 可用

**结果**：飞机上色干净、涂装方向正确、无块状串色。216.5 s / 13.7 GB / 83°C，GLB 7.14 MB（120k 面、2048² albedo+MR）。

**推翻的旧判断**：Codex 那版青绿块**不是 UV 边界溢色**。

| 处理 | 渲染色相 σ | 青绿占比 |
|---|---|---|
| 原始 | 12.68° | 23.96% |
| UV 岛掩膜 + dilation 12px | 12.66° | 23.96% ← 零变化 |
| dilation + 岛内中值协调 | **8.32°（−34%）** | 22.5% |

真因：**多视图反投影把外套青绿抹进了裤子/靴子的 chart 内部**。正解是把跨缝 3D 邻接一致性做进烘焙阶段。

**产品化**：主实例的 TexGen 会白下 11 GB（写死 `snapshot_download`，不认本地权重）。已给 `multiview_utils.py` 打本地路径补丁，**重启 ComfyUI 生效**；未生效前用隔离实例跑。

## 二、骨骼线：模板骨架 + 热扩散，够用且快

`auto_rig.py`：任意水密网格 → 带 skin 的 GLB（`JOINTS_0`/`WEIGHTS_0`/`inverseBindMatrices` 全在）+ 骨骼线渲染图。

| 输入 | 模板 | 顶点 | 骨数 | 无权重顶点 | p99 撕裂 | 耗时 |
|---|---|---|---|---|---|---|
| 兔子（坐姿） | chain | 100k | 10 | 0 | 1.13 | 41 s |
| 兔子 | quadruped | 100k | 19 | 0 | **2.12（16.3%H）** | 48 s |
| 飞机 | aircraft | 203k | 14 | 0 | 1.21 | 68 s |
| 人形（迈步姿态） | humanoid | 50k | 21 | 0 | **5.03（17.7%H）** | 30 s |

**模板法的死穴是非中性姿势**：坐姿兔子有 11/19 根骨在体外；迈步人形的对称腿骨落在两腿间空气里。
`chain`（网格自采样链）在同输入上撕裂 0.13%。→ **默认先试模板，撕裂超阈值自动回退 chain**（`rig_gate.py` 已实现，6 个 report 3 PASS / 3 FAIL）。

**RigAnything 能跑**（离线自检 PASS，195M 参数 / 0.36 GB fp16），UniRig **不能跑**（硬 import flash_attn，FA2 无 sm70 内核，要改 3 处约 0.5–1 天）。

## 三、运动：BVH 重定向，全线达标

`retarget_lib.py`：`retarget_bvh(...)`，换一条动作 = 1 次调用，8 个 job 合计 37.3 s，纯 CPU。

| action | 帧 | 穿地 | 滑移 | 支撑帧 L/R |
|---|---|---|---|---|
| walk 02_01 | 24 | **0.000** | 7.39 | 12/16 |
| wave 111_37 | 64 | **0.000** | **1.23** | 1/64 |
| bow 113_02 | 89 | **0.000** | 7.56 | 86/72 |
| idle 77_02 | 24 | **0.000** | 7.37 | 0/24 |
| run 09_01 | 18 | **0.000** | 14.97（未达标，接触相位太短） | 9/9 |

对比旧 FK 版：穿地 35.46 → 0、滑移 16.25 → 7.39、躯干扭转 0 → 14.5°、**手臂-对侧腿相关 −0.099 → +0.90**。

**两个教训**：
- 指标不能替代看图：`111_02 Bow` 指标全绿但渲染是**单腿后举的鱼跃**（舞台式鞠躬），`支撑帧 L=1` 早就在报警
- `ankle_gain` 0.6 让 walk 滑移 7.39 → **4.19**，但让 run 反而恶化到 35.74 —— 该指标对接触时长敏感，不能跨步态横比

**未闭合**：待机左脚浮空 21 mm（撑地只按全局最低点）。修法：启用 IK 约束逐腿落地。

## 四、精度：Direct3D-V3 在 V100 上跑通

**flash-attn 兼容层**：纯 PyTorch SDPA 重写三个入口，17/17 对拍通过。
- fp16 @V100：qkvpacked 4.71e-4 / varlen_qkvpacked 1.01e-3 / varlen_kvpacked 5.68e-4
- CPU fp32 同用例 ≤6e-7（证明误差来自 fp16 本身）
- 真仓库模块上：窗口自注意、CrossAttention、小号 SparseDiT 端到端全部 ≤1.2e-3

**实测两次**（输入 `assets/input_imgs/6.png` + 配对粗网格）：

| | 4 步 | 15 步 |
|---|---|---|
| 端到端 | **32.5 s** | **56.4 s** |
| 单步 | 2.74 s（稳态 1.96） | 1.98 s |
| 峰值显存 | 5098 MiB | 5098 MiB |
| 面数 | 1.73 M | 1.79 M |
| 水密 | True | **True** |
| 温度 | 63°C | 61→69°C |

输出是持矛骑乘武将（不是噪声）。**但 1290 个连通分量，1275 个 <100 面的碎壳**（占 0.86% 面）——落地打印前必须过滤小壳。

**换算表**（512 denoiser 实测，CFG 单次前向）：

| token | 单步(CFG=2×) | 峰值 reserved |
|---|---|---|
| 11.7 k（512 档实际） | **1.96 s** | 4.0 GiB |
| 45.4 k（≈1024） | 6.7 s | 8.3 GiB |
| 114.3 k（≈1536） | 27.2 s | 16.9 GiB |

推演：512 端到端 56 s（产品级）、1024 约 2.5–3.5 min、1536 约 8–10 min。

**硬瓶颈**：V100 上 SDPA 只能走 EFFICIENT_ATTENTION（**26 TFLOPS**，V100 fp16 理论 112）；flash/cuDNN 后端直接 `No available kernel`；math 后端 5 TFLOPS 且 24.8 GiB 直接 OOM。

## 五、多视图：管线没问题，锅在照片

| 组 | 四视图 IoU | 表面误差中位 |
|---|---|---|
| 源模型自测（基准） | 0.998 | 0 / 0 |
| **理想输入**（4 张正交 0° 同尺度） | **0.709** | **1.12 mm** |
| 不一致A（back 用镜像） | 0.735 | 1.13 mm |
| 不一致B（**只坏一张**：22° 仰角 + 0.92 尺度） | **0.613** | **2.48 mm** |

**只坏一张视图就掉 13%**，那张视图的 IoU 塌到 0.19、表面误差翻倍。这解释了真实照片为什么只有 0.267。

**方法论教训**：照片参照 IoU 会**奖励"变胖变钝"**（B 组反而拿到最高辅助分 0.4386），不能当主判据。

## 六、低显存：12G 只能跑 2mini@384

| 档位 | 峰值总显存 | 增量 | 耗时 | 最小可行显存 |
|---|---|---|---|---|
| 2.1 @512 | 15113 MiB | 14193 | 440 s | 15.9 GB |
| 2.1 @768 | 19608 MiB | 18688 | 1267 s | 20.3 GB |
| 2mini @512 | 15138 MiB | 14218 | 225 s | 15.9 GB |
| **2mini @384** | **6243 MiB** | 5323 | 116 s | **7.2 GB** |
| 2mv @512 | **32107 MiB** | 31187 | 330 s | 32.1 GB（32G 独占） |

**反直觉**：2.1 的峰值在**扩散采样**不在解码，512 和 768 采样峰值几乎一样 → 降 octree 只对 768→512 有效。2mv 必须 32G 独占。

**口径警告**：2mini 的 torch 统计只有 5.5 GB、nvidia-smi 是 15.1 GB（体素解码走 PyTorch 之外的 CUDA 扩展）→ **评估显存只信 nvidia-smi**。

## 七、跨方向的七条环境事实（写进共识，别再踩）

1. **这台机器没有 OpenGL**（V100 TCC 模式）：EEVEE / WORKBENCH 必崩，渲染只能 Cycles CPU
2. **V100 的 SDPA 只有 EFFICIENT_ATTENTION**（26 TFLOPS）：任何依赖 FA2 的项目要么改 SDPA（慢 3–5 倍），要么放弃
3. **fp8 不可用**（需 sm89+）；bf16 无原生（`is_bf16_supported()` 返回 True 是模拟）
4. **`import bpy` 必须早于 trimesh/torch**，否则 `DLL load failed`（Windows）
5. **trimesh 5.0 读 rigged GLB 会丢 skin/weights** → 前端用 Three.js `GLTFLoader`，后端导 STL 走 rest pose
6. **trimesh 读 GLB 后 UV 是 OpenGL 约定**，取样必须 `row = (1 - v)`，反了整机变迷彩
7. **Python 3.8+ 扩展模块依赖 DLL 不走 PATH**，必须 `os.add_dll_directory()`

## 九、追加实测（2026-11-26 13:40）

### ① 多视图结论反转：真实照片是**最好的**一档

**之前我记的「真实照片 0.267 / 0.311，比单图差」作废。**原因是**预遮罩**：

`LoadImage` 会把图转成 RGB 三通道 → `Multi_Background_Remover` **必然重跑 birefnet**。
喂「透明底 / 黑底」进去，birefnet 在非白底上抠出的 mask 是坏的 —— 遮罩不是没起作用，是**起了反作用**。

| 输入 | eval（照片参照，辅助） | 四视图 IoU | geo 中位 |
|---|---|---|---|
| plane_21 自己（单图基线） | 0.4709 | 0.998 | 0 |
| 理想输入（自 plane_21 渲染） | 0.4067 | 0.709 | 1.12 mm |
| **真实照片·白底原图直出** | **0.4872** | 0.636 | 2.29 mm |
| 真实照片·外部正交化后 | 0.4895 | 0.636 | 1.77 mm |
| 旧版（预遮罩） | 0.3112 | 0.434 | 6.53 mm |

**新规则**：喂**白底原图**，不要预遮罩、不要外部归一化。
这是本项目第一次证明**多视图对真实照片是正收益**（0.4872 > 单图 0.4709）。

正交化本身**不值得做**：`MVImageProcessorV2.recenter()` 已经按 alpha bbox 裁切 + 最大边缩放 + 居中，
外部再做高度/留白/居中纯属冗余（IoU 0.6357 → 0.6362，噪声内）。

### ② Direct3D-V3 1024 档：能跑，但收益很小

| | 512 @4 步 | 1024 @4 步 |
|---|---|---|
| 端到端 | **32.5 s** | **82.7 s** |
| 单步 | 2.74 s | **15.65 s** |
| 峰值 reserved | 5.8 GiB | **10.0 GiB** |
| 峰值显存(设备) | — | **16.0 GB** |
| 面数 | 1.73 M | **7.44 M** |
| 三角边长中位 | 2.0 mm | **1.0 mm** |
| 水密 | True | True |
| 峰值温度 | 69°C | **86°C**（超 84°C 红线） |

**关键判据**：512 采样点到 1024 表面的距离 **中位 1.0 mm / P90 4 mm / 最大 14 mm**（模型 600×900×400 mm）。
也就是说 1024 基本是把同一形状细分了一遍，不是长出新细节。

**结论**：Direct3D-V3 用 **512 档 4 步**（32.5 s / 5.8 GiB）当产品级精修；1024 只在"要更细三角面"时用，且注意 86°C。

### ③ 采样线程命名坑

精度脚本的 GPU 采样线程把 `self._stop` 当 Event，和 `Thread._stop()` 撞名，
`join()` 时报 `TypeError: 'Event' object is not callable` —— **15 步跑完但产物没落盘**。
已改名 `_stop_evt`。自己写采样线程必须避开 `_stop`。

### ④ 尺度不一致是免费的，角度不一致才贵（决定性对照）

四张理想视图物体大小拉开 **2.2 倍**（0.62/1.00/1.35/0.80，只改尺度不改角度）：

| 组 | 四视图 IoU | geo 中位 / P90 |
|---|---|---|
| 理想输入（同尺度） | 0.709 | 1.13 / 2.99 mm |
| **尺度差 2.2 倍** | **0.744** | 1.14 / 2.64 mm |
| 只改一张角度（22° 仰角） | 0.613 | **2.48 / 6.68 mm** |

**尺度差几乎零代价，角度差代价翻倍。** 因为 `recenter()` 按每张自己的 bbox 最大边重归一。

**所以拍照规范只有一条硬要求：四张同仰角、方位严格 90°，物体在画布里多大无所谓。**
像素级预处理（正交化、尺度归一、留白统一）全部可以省掉。
